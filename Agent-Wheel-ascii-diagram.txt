AGENT WHEEL 2.1 - ONE VERTICAL, FULL-CIRCLE ASCII BUILD GUIDE
LAW REVISION 7 - 2026-09-17. Project agent routes, models, reasoning, and budget are operational controls in the Inspector.
The Spec describes the product and never configures Agent Wheel's own agents. New Specs reject route_allowlist and budget fields.
Historical accepted versions and events remain intact. Old events replay their original settings behavior; the first new event
moves the project to independent controls without changing accepted content, existing seat choices, or the current budget.

THE INVARIANT: a seat sees only the frontier - the collapsed wiki of every kind plus the expanded nodes and leaves it is working -
and there is nothing else to read. Looking is reading the Super Document. Changing is writing, in exactly two places: a node version
through the Form Service, or a leaf on a branch. Nothing is written off as untrue or broken until every leaf has been looked at.
A change to any node is living and current at the very next look; drop-down is only the bookkeeping of what must be looked at again.

THE SPLIT: a read is a map and a slice. The map is every kind and every Plan leaf as a one-line stub; the slice is the full text of
what this turn works. A seat that needs more names ids and is looked at again. A write is a gate action or a reopen; nothing else
moves a node or a leaf, and no read ever does. The two are never one mechanism: expanding is not reopening, pulling is not editing,
and a stub is not a gap.

This file is the law. When code, README, packaging, or any other document disagrees with it, this file wins. It lives at the
repository root under this exact name; paths.js, build-app.sh, package.json, and README point here and may not be re-pointed.
Nothing edits this file inside a build. If a clause is impossible or self-contradictory, the builder stops and reports the clause.

READ ORDER: this file -> build docs/00-READ-ORDER.md -> nothing else is normative. build docs/Agent-Wheel-spec.docx is the owner's
dictation record, absorbed into section 4 where it still applies. The Convobus documents under build docs/ are upstream reference
only.

Every lifecycle arrow and every outbound seat message invokes THE WHEEL below.
Top = Idea.problem + Idea.solution. Bottom = the Idea's solution, satisfied. The outer return proves the artifact back to the root.

| 0. DEFINITIONS - EVERY TERM BELOW MEANS EXACTLY THIS AND NOTHING WIDER                                             |               |
|-----------------------------------------------------------------------                                             |               |
| dispatch = one outbound ConvoBus card to a model seat. Human replies, the deterministic validate seat, and local   |               |
| handlers are not dispatches.                                                                                       |               |
| material decision = every Plan node of kind decision. Nothing else is material; no model judges materiality.       |               |
| high-risk leaf = a leaf whose trial or execution needs network, credentials, deletion, publish, or execution       |               |
| outside app-managed scratch or its branch, or whose effect is irreversible. The shipped test is a keyword match    |               |
| over the leaf's title (HIGH_RISK_RE); it approximates this definition and is not the definition.                   |               |
| material change = every new accepted version of any node. There are no non-material edits and no typo exception.   |               |
| Its effect is computed by claim diff (DROP-DOWN): a version whose claims are unchanged stales nothing. A seat      |               |
| assignment or budget change is operational: it moves no product node and invalidates no claim.                |               |
| alternatives = the candidate methods compared inside Plan Trial for one decision leaf. The chosen alternative is   |               |
| the approach; there is no node named Approach.                                                                     |               |
| Look 1 = the context compile at STAGING. Look 2 = the re-run of drop-down, frontier, and Super Document hash       |               |
| immediately before egress; any difference restages.                                                                |               |
| Reopen = a successor draft of an accepted node in the same project; drop-down applies. Fork = a new project whose  |               |
| Idea cites the parent version; the parent is untouched. There is no third operation.                               |               |
| solo mode = one human and one configured route.                                                                    |               |
| outcome = the one classification every back card carries: result | malformed | transport_error | timeout | refused |               |
| (see THE WHEEL).                                                                                                   |               |
| Core = the ConvoBus files named in the CORE MANIFEST (section 6). Adapter = agentwheel/lib/transport/, the only    |               |
| code that touches Core.                                                                                            |               |
| authored_by = a field on every node version: human | seat | system. idea, experience, spec are human; design is    |               |
| human or seat (Leader); plan is system-generated and its leaves are executed by the Builder seat. Authorship is    |               |
| read from the field, never inferred from the kind.                                                                 |               |
| identical gap = the same claim id from the same author, keyed on claim_refs, gapped on two consecutive trials.     |               |
| Never keyed on leaf id. The count resets when the claim itself changes and keeps running across NODE_STANDS.       |               |
| engine-executed = the engine ran it in scratch or on a branch and recorded the exit code. Engine-executed is not   |               |
| proven: the trial engine believes exit zero.                                                                       |               |
| living plan = the Plan is the only place work is recorded and the only thing a seat ever works from. Every Super   |               |
| Document carries the current Plan. A leaf is untried | passed | gap | conflict | executing | done | stale; there   |               |
| is no separate Work node.                                                                                          |               |
| seat assignment = the operational map seat -> route (Leader, Builder, Reviewer), audited as an event, constrained  |               |
| by the registered route catalog. Changing it never drops down.                                                         |               |
| Done = a project state (purple), never a node. It is reached only by final closure and lost the moment any leaf    |               |
| leaves done.                                                                                                       |               |
| claim = one identified statement a leaf can serve: an Idea problem concern or solution criterion, an Experience    |               |
| acceptance criterion, a Design claim, a Spec requirement or constraint. Claims carry stable ids across versions; a |               |
| diff of two versions is a diff of their claims.                                                                    |               |
| map = every spine kind and every Plan leaf as a one-line stub; every Super Document carries the whole map. slice = |               |
| the full bodies this turn works: the current node, the reopened or stale nodes, the prompt-touched nodes, the next |               |
| Plan group, the leaves a claim change sent back, and the ids a pull named. cited claims = the claims the slice     |               |
| names: the claim_refs of every expanded leaf, the claim a finding or gate carries, and the changed claims. An      |               |
| accepted ancestor outside the slice is its stub plus its cited claims with their text, and nothing else of it.     |               |
| pull = requested_expansions on a seat result: the ids the seat needs in full, each a spine kind or a Plan leaf id  |               |
| present in the map, at most eight. A pull is a read: one redispatch per turn with those ids in the slice, counted  |               |
| as a dispatch, audited. It is never a reopen and stales nothing.                                                   |               |
| shelved = a staged seat-authored result under a node a fail-up reopened - a staged version of that node, or a seat |               |
| result awaiting validation that was compiled against it - set aside by one event: never validated, never staged    |               |
| again, never a schema attempt; read-only history a later dispatch may carry as its previous attempt.               |               |
| previous attempt = what a redispatch carries for the same leaves or the same node: the newest returned, shelved,   |               |
| or stale attempt that overlaps, with its tests and files, and why it is there - returned by review, failed its     |               |
| tests, or staled by <kind> v<n>: <claim ids>. It is context inside the Super Document, never a node and never a    |               |
| leaf state.                                                                                                        |               |

| 1. IDEA ROOT - PROBLEM + SOLUTION - SYSTEM LOCKED                                                                  |               |
|--------------------------------------------------                                                                  |               |
| Lifecycle starts here. There is one Idea node per project. Its solution field is what Done must equal.             |               |
|                                                                                                                    |               |
| Closed UI: show only ProjectState.name, for example: Bookmaker.                                                    |               |
| Expanded UI: Project name plus six helper chips and exactly two canonical Idea fields:                             |               |
|   problem  = what is failing, for whom, and in what situation                                                      |               |
|   solution = the observable success state that would mean the problem is solved                                    |               |
| The six chips are transient prompts. They are not fields and are never stored. Their exact text is law:            |               |
|   problem:  "Who hurts today, and in what moment?"  |  "What breaks or drags without this?"  |  "What do people    |               |
|   fall back on right now?"                                                                                         |               |
|   solution: "What must be true the moment it is solved?"  |  "What does success look like on one screen?"  |       |               |
|   "What is the smallest complete win?"                                                                             |               |
|                                                                                                                    |               |
| Entry paths: the project rail's New Project (names the project and opens this form - the primary path); typed      |               |
| form; natural language -> parsed draft form -> human confirm/edit; /spool in the composer; MCP spool_project.      |               |
| MCP is used only for spool_project from main chat. Every other rule in this diagram is internal system             |               |
| enforcement.                                                                                                       |               |
|                                                                                                                    |               |
| Canonical Idea body is strict JSON Schema with only problem and solution. Unknown fields are refused at the Form   |               |
| Service, before commit. No canonical node body is Markdown.                                                        |               |
| Accept creates an immutable version and system-locks the Idea. Reopen previews every leaf that will go back to     |               |
| untried, confirms, then invalidates by claim. Fork copies nothing downward.                                        |               |
|                                                                                                                    |               |
| NATIVE SHELL - THE PRODUCT ENVELOPE AROUND THIS ENTIRE FLOW:                                                       |               |
|   One installed Agent Wheel.app. AppKit: one NSStatusItem, one NSWindow holding one WKWebView that loads bundled   |               |
|   HTML only. Its navigation delegate refuses every URL that is not the bundle or the tokened loopback API. No      |               |
|   external browser, no dev-server UI, no `open http://` anywhere in the product.                                   |               |
|   The Node 26 helper is a child process of the app. The app starts it, writes the launch token to its stdin (never |               |
|   argv, env, or disk), restarts it if it dies, shows RECOVERY_REQUIRED_V1 when it does, and stops it on Quit. It   |               |
|   is the app's child and nothing else: the product installs no launchd job, and after install and after Quit no    |               |
|   launchd job whose label contains agent-wheel exists on the machine.                                              |               |
|   Swift is compiled with swiftc by scripts/build-native-app.sh following the vendored Convobus 0.2.0 pattern. No   |               |
|   SwiftUI-only shell, no Electron, no Tauri, no framework not already in the repo.                                 |               |
|   Keychain: the Swift shell alone reads and writes Keychain items via Security.framework and hands secrets to the  |               |
|   helper in memory over the tokened loopback. The helper never spawns /usr/bin/security and never persists a       |               |
|   secret. Keys exist only for the optional api routes; app and CLI routes need none, and the product is built      |               |
|   around them.                                                                                                     |               |
|   Main window: project rail with New Project and one row per project; status/stage/budget header; only the current |               |
|   node expanded; the inspector shows the seat assignment, model and reasoning choices, the budget window      |               |
|   and count, set there, and route health. The route table and the API keys are the machine's, on its own page.     |               |
|   A fixed but secondary natural-language composer. Every closed node shows its name only. No stack of empty        |               |
|   future accordions, raw IDs, MCP terms, or debug states in normal UI.                                             |               |
|   Names carry no slashes and no aliases: Idea, Experience, Design, Spec, Plan, Done.                               |               |
|   Signing: ad-hoc (codesign -s -), not notarized. Stated consequence: an ad-hoc identity changes every build, so   |               |
|   Accessibility (every ax route) and Keychain access re-prompt after each rebuild. Developer ID + notarization is  |               |
|   a named later Spec item.                                                                                         |               |

|-------------------------------------------------------------                                                       |               |
| Closed UI: Spec only. Expanded UI: strict requirements/constraints form.                                           |               |

| 5. PLAN - THE LIVING PLAN: GENERATED, TRIED READ-ONLY, THEN EXECUTED LEAF BY LEAF                                  |               |
|----------------------------------------------------------------------------------                                  |               |
| The Plan is always generated automatically from the exact accepted Idea, Experience, Design, and Spec versions.    |               |
| There is no manual Plan path and no other record of work.                                                          |               |
| Map every Idea problem concern and solution success criterion, every Experience acceptance criterion, every Design |               |
| claim, and every Spec rule to Plan steps, tests, guards, evidence, and expected artifacts. Every leaf carries      |               |
| claim_refs naming the ids it serves.                                                                               |               |
|                                                                                                                    |               |
| PLAN GRAPH LAW:                                                                                                    |               |
|   decomposes_into[] = hierarchy; needs[] = required dependency; after[] = legal order (the inverse is derived,     |               |
|   never stored); serves[] / claim_refs[] = upward proof.                                                           |               |
|   Node kinds: decision | action | assumption | expected_result | loop. The graph is a DAG. Repetition is a typed   |               |
|   loop node, not a graph cycle.                                                                                    |               |
|   A leaf is one testable decision, action, assumption, or expected result with no unresolved child/dependency. If  |               |
|   it cannot be tried, decompose it further.                                                                        |               |
|                                                                                                                    |               |
| PLAN TRIAL LAW - enforced by wheel state and Tool Broker, not by asking the model politely:                        |               |
|   1. Compute topological trial stages and traverse every reachable required connected node to terminal leaves.     |               |
|   2. Try independent leaves in parallel only when seats, route capacity, and budget permit. In this drop one seat  |               |
|   runs at a time; the frontier queues.                                                                             |               |
|   3. Applicability is owned by the leaf kind, not the kit. action leaves and expected_result leaves require        |               |
|   executable_test applicable: the kit may add derivations, it cannot opt out of the run. assumption leaves may be  |               |
|   derivation-only. Record a real reason for every non-applicable basis. Every evidence[] entry carries executor:   |               |
|   engine | model. No text length counts as evidence. Engine-executed is not proven: the trial engine believes exit |               |
|   zero, which is why the Reviewer is the last reader of every kit - a seat, not a step, and not a courtesy.        |               |
|   4. Every decision leaf compares at least two alternatives, or proves with engine evidence that only one is       |               |
|   feasible. The chosen alternative is recorded on the leaf; it is the approach.                                    |               |
|   5. High-risk leaves (section 0) require two independent evidence methods plus a human gate unless Spec narrowly  |               |
|   preauthorizes the action.                                                                                        |               |
|   6. Roll up bottom-up. No parent passes while any required descendant is untried, gap, conflict, or missing       |               |
|   evidence.                                                                                                        |               |
|                                                                                                                    |               |
| During Plan Trial: canonical/project/main/branch/artifact/release/publish writes are denied. App-managed           |               |
| disposable scratch (outside the repo) is allowed and cannot flow into an execution without review.                 |               |
| Plan Skip skips optional human review only after the full system trial closes. It never skips a leaf, evidence,    |               |
| gap, conflict, or write lock.                                                                                      |               |
|                                                                                                                    |               |
| PLAN CLOSURE PROOF - deterministic, before any execution: every Design claim, Spec rule, and Experience criterion  |               |
| maps to a passed leaf through claim_refs; every decision leaf has a chosen alternative; no gap, conflict, or stale |               |
| dependency remains. A failure opens REPAIR_REQUIRED on the claim's author. PLAN_READY (SUMMARIZE | SKIP_REVIEW |   |               |
| APPROVE) follows.                                                                                                  |               |
|                                                                                                                    |               |
| EXECUTION LAW - the plan is worked, not a separate node:                                                           |               |
|   EXECUTION_UNLOCKED = plan closure proof passed + PLAN_READY approved + budget/route/gates clear. Nothing writes  |               |
|   before it.                                                                                                       |               |
|   The Builder executes one leaf, or one after[]-ordered group of leaves, per dispatch, on an isolated branch (Git  |               |
|   worktree or copy-on-write snapshot) recording base versions/hash, the leaf ids, paths, tools, route, and         |               |
|   expected result. A submission is files + tests + optional build_command; the engine runs the build and the tests |               |
|   in the branch before anything else sees it. Failing tests fail up.                                               |               |
|   The Reviewer, independent, accepts or returns gap | conflict | needs_human. Accept merges the branch to main and |               |
|   marks the leaves done; main is strictly sequential; no last-writer-wins.                                         |               |
|   The artifact grows on main. A leaf is done only when its tests pass on main. A parent is done when every         |               |
|   required descendant is done.                                                                                     |               |
|   REPAIR, NOT RESTART: a Builder dispatch after a return or a reopen carries the previous attempt for its leaves - |               |
|   the newest returned or stale execution whose leaves overlap the group's - marked why it is there: returned by    |               |
|   review, failed its tests, or staled by <kind> v<n>: <claim ids> (the kind, the version, and the claim ids that   |               |
|   moved), with its files offered as the starting point. The Builder's submission repairs those files rather than   |               |
|   starting over; the branch is still cut from main, as every branch is. Done leaves stay done: a reopen            |               |
|   re-executes nothing whose claims did not move.                                                                   |               |
|   Every Super Document a seat receives carries the current Plan as map and slice: the next group's leaves, the     |               |
|   leaves a claim change sent back, and the leaves a pull named expanded with their state and execution; every      |               |
|   other leaf a stub (id, title, kind, claim_refs, state), with the Wiki Temp map. A fresh Plan is not expanded     |               |
|   whole because its leaves are untried. What the agent sees is always the plan as it stands.                       |               |

| 6. SEATS, ROUTES, AND TRANSPORT                                                                                    |               |
|--------------------------------                                                                                    |               |
| SEATS: Leader proposes Design and authors trial kits. Builder executes leaves. Reviewer reviews every result       |               |
| independently and never authors. Repair, schema-repair, and final-closure dispatches ride the seat whose result    |               |
| they concern. One agent works at a time in this drop; parallel seats are a later Spec item.                        |               |
| SEAT ASSIGNMENT: default Leader = grok:cli, Builder = grok:cli, Reviewer = chatgpt:codex. A different route for    |               |
| the Reviewer is what makes review rung 1 (a different route) the default; when the assignment gives the Reviewer   |               |
| the author's route, rung 2 (fresh context, no author reasoning) applies and is recorded. The assignment is changed |               |
| in the inspector, audited as an event, constrained by the registered route catalog, never a drop-down.                       |               |
| Agents use the same authenticated typed Form Service and strict schemas as the human. They do not edit canonical   |               |
| JSON or bypass the UI contract.                                                                                    |               |
| ROUTE CAPACITY (machine-wide): ax and applescript methods = 1 (one GUI); stdio = one process per binary per        |               |
| project, at most three machine-wide; api = the provider's rate limit with exponential backoff. The frontier        |               |
| queues; it never interleaves two projects on a capacity-1 route.                                                   |               |
|                                                                                                                    |               |
| CONVOBUS CORE IS THE PACKAGED TRANSPORT AUTHORITY:                                                                 |               |
|   Owns cards, card IDs, exact provider/project/App-CLI-API route, route readiness, delivery attempts, out->back    |               |
|   lifecycle, reply correlation, pause/attention/failure, checkpoint, and shutdown.                                 |               |
|   Agent Wheel owns lifecycle, nodes, frontier, prompts, Plan Trial, execution, gates, budget, seats, permissions,  |               |
|   branches, review, commits, proof, and Done.                                                                      |               |
|   One embedded helper, one private transport store (section 4). Never a second Convobus GUI, never a shared        |               |
|   writable store, never Convobus Loops advancing main.                                                             |               |
|   CardBinding joins card_id to project/turn/attempt/seat/branch/route/context hash/base versions/result schema     |               |
|   without duplicating the card state machine. Recovery reconciles every adapter in-flight record against           |               |
|   CardBinding: a card with no live seat is closed as transport_error, and a route is never left occupied by a dead |               |
|   card.                                                                                                            |               |
|   Exact route must be ready; no silent fallback.                                                                   |               |
|                                                                                                                    |               |
| CORE MANIFEST - the exact ConvoBus 0.2.0 files that ship, from Convobus/convobus-0.2.0-source/lib/:                |               |
|   card.js, providers.js, provider-catalog.json, seats.js, turn.js, control.js, store.js, methods/stdio.js,         |               |
|   methods/ax.js, methods/applescript.js, methods/filewins.js, methods/cursor-cdp.js, jxa/ax.js, and the ax-helper  |               |

| THE WHEEL - RUNS AT EVERY ARROW AND BEFORE EVERY OUTBOUND MESSAGE                                                  |               |
|------------------------------------------------------------------                                                  |               |
| Applies to Leader, Builder, Reviewer, repair, schema-repair, final-closure, automatic continuation, and            |               |
| user-facing result cards. Nothing leaves a seat unchecked.                                                         |               |
|                                                                                                                    |               |
| OPEN                                                                                                               |               |
|   Human/system submits a legal typed form proposal, natural-language message, gate action, seat assignment change, |               |
|   or automatic continuation.                                                                                       |               |
|                                                                                                                    |               |
| STAGING - the prompt/action is still uncommitted                                                                   |               |
|   Create turn_id + attempt_id; record raw input; freeze candidate base versions; disable canonical editing;        |               |
|   acquire/prepare the project lease. This is Look 1.                                                               |               |
|                                                                                                                    |               |
| STATE WATCHER - deterministic internal code answers WHEN to recompute                                              |               |
|   Triggers on form/chat action, node/gate/trial/execution change, route/card event, branch settlement, conflict,   |               |
|   budget, external repo hash, pause/recovery, or artifact change.                                                  |               |
|   An OS file watcher may emit a change event; it never selects nodes or grants writes.                             |               |
|   The watcher ticks on a fixed short period while nothing is refused. After an egress refusal it backs off - 5 s,  |               |
|   30 s, then every 60 s - until any new event on the project resets it; the refusal is audited when the failing    |               |
|   guard set changes, not on every tick.                                                                            |               |
|                                                                                                                    |               |
| DROP-DOWN CHECK - before context compilation                                                                       |               |
|   Changed/reopened/rejected/dropped/superseded parent -> diff its claims against the last version -> send the      |               |
|   leaves that serve changed or removed claims, and everything that needs them, back to untried with their trials,  |               |
|   executions, tests, evidence, waivers, and branch bases; generate leaves for new claims; leave every other leaf   |               |
|   as it was; remove purple when any leaf moves (TRAVERSAL).                                                        |               |
|                                                                                                                    |               |
| FRONTIER RESOLVER - deterministic rules answer WHICH exact node versions and which Plan leaves are current         |               |
|   blocking gate/error -> current lifecycle node -> prompt-touched/edited nodes -> stale/changed nodes -> the Plan  |               |
|   leaves whose state can move next -> required decomposition/dependencies -> branch results -> legal               |               |
|   predecessor/successor -> collapsed orientation stubs.                                                            |               |
|   Do not expand all history merely because it exists, and do not expand an ancestor merely because it is accepted. |               |
|                                                                                                                    |               |
| DOUBLE-LOOK CONTEXT PIPELINE - fresh and immutable for every turn                                                  |               |
|   Canonical JSON node versions                                                                                     |               |
|     -> Frontier Snapshot JSON: ordered selected versions and leaves + inclusion reasons + blockers + legal next    |               |
|     kinds                                                                                                          |               |
|     -> Wiki Temp Snapshot JSON: temporary Wikilink-like map of the five nodes and the Plan's parents + collapsed   |               |
|     stubs; not canonical; not Markdown                                                                             |               |
|     -> Expanded Context JSON: the slice - full bodies for the current node, the reopened or stale nodes, the       |               |
|     prompt-touched nodes, the next Plan group, the leaves a claim change sent back, and the ids a pull named.      |               |
|     Every accepted ancestor outside the slice is its stub plus its cited claims with their text, never its whole   |               |
|     body. A turn that edits an ancestor has it reopened or prompt-touched, so it is in the slice by that rule and  |               |
|     by no other.                                                                                                   |               |
|     -> Super Document JSON: current map + the slice + prompts + gate + seat/role/branch + exact route +            |               |
|     permissions + budget + evidence + previous attempt when one exists (section 0) + result schema + base versions |               |

|   Look 2 re-runs drop-down and the frontier and recomputes the hash immediately before egress; a changed hash      |               |
|   restages instead of sending.                                                                                     |               |
|                                                                                                                    |               |
| PULL - A READ, NEVER A WRITE                                                                                       |               |
|   Every seat result schema (trial kit, Design proposal, execution submission, review result) carries optional      |               |
|   requested_expansions: at most eight ids, each a spine kind or a Plan leaf id present in the map. For the Design  |               |
|   proposal the seat's result schema is the Design form plus that one field; the Form Service strips it before the  |               |
|   node body is validated, so no node body ever carries a pull.                                                     |               |
|   A result whose requested_expansions is non-empty is not staged and not reviewed: the engine records              |               |
|   pull_requested with the ids, keeps the turn_id, takes a new attempt_id, recompiles both Looks with those ids in  |               |
|   the slice, and sends once to the same seat on the same route, the pulling result riding along as its previous    |               |
|   attempt. That redispatch is a dispatch: it counts against the budget, passes every egress guard, seals a new     |               |
|   hash, and is audited with the ids.                                                                               |               |
|   One pull per turn. A second pull, an id not in the map, a path, a glob, "all", or "the repo" is refused -        |               |
|   audited as pull_refused with the offending entry - and the result is then read on its content alone. Unnamed     |               |
|   stubs stay stubs. A pull reopens nothing and stales nothing; the claim does not move. It is a read jump, not a   |               |
|   write jump: traversal, not a gate.                                                                               |               |

| TRAVERSAL - CONTEXT, WORKFLOW, PROOF, FAIL-UP, AND DROP-DOWN                                                       |               |
|-------------------------------------------------------------                                                       |               |
| CONTEXT TRAVERSAL: every turn; follow the selected Frontier/Wikilinks only far enough to expand the current nodes  |               |
| and leaves required for the action.                                                                                |               |
| WORKFLOW TRAVERSAL: every legal stage movement; Idea -> Experience -> Design -> Spec -> Plan (trial, then          |               |
| execution) -> Done.                                                                                                |               |
| PROOF TRAVERSAL: after Plan Trial (closure proof), after every material upstream/artifact change, and before Done  |               |
| (final closure).                                                                                                   |               |
|                                                                                                                    |               |
| FAIL-UP - a failure walks toward the root and reopens the earliest responsible ancestor, not merely the latest     |               |
| visible stage:                                                                                                     |               |
|   Artifact / executed leaf -> Plan -> Spec -> Design -> Experience -> Idea.problem + Idea.solution.                |               |
|   First move: a trial-time gap suspects the kit and reopens the leaf's trial; a failing execution reopens the      |               |
|   leaf. The first move, not the only move. Three actors walk further, each its own way:                            |               |
|   A Reviewer naming plan (or a seat-authored design) fails up there. A Reviewer naming idea, experience, spec, or  |               |
|   a human-authored design opens HUMAN_ESCALATION carrying the target and reopens nothing.                          |               |
|   A human REJECT(target) walks to the chosen target, default design. The human already answered.                   |               |
|   The second identical gap is a mechanical walk to the claim author by claim_refs, including spec and design. No   |               |
|   model in that loop.                                                                                              |               |
|   Every fail-up actor - EDIT_NODE, REJECT(target), the identical-gap walk, and failUp itself - shelves any staged  |               |
|   seat-authored result under the node it reopens: one event moves it from staged to shelved, its pending           |               |
|   validation is cleared, and the watcher has nothing left to stage. A shelved result is never validated, never     |               |
|   staged again, and never a schema attempt; it is read-only history the next dispatch may carry as its previous    |               |
|   attempt. A reopen that leaves a seat result staged is a bug, not a state.                                        |               |
|                                                                                                                    |               |
| DROP-DOWN - walks by claim, not by position:                                                                       |               |
|   A new accepted version is diffed against the last by claim id. Leaves whose claim_refs name a changed or removed |               |
|   claim go back to untried, together with everything that needs them or decomposes from them, and their            |               |
|   TrialRecords, executions, tests/evidence, WaiverRecords, and branch bases go with them. New claims generate new  |               |
|   untried leaves. Every other leaf stays exactly as it was - done stays done, passed stays passed.                 |               |
|   The frontier then carries the changed claims expanded and the leaves it sent back in the slice, so the next look |               |
|   - and the Reviewer - sees the change against what still stands. Nothing is written off until the affected leaves |               |
|   have been looked at again.                                                                                       |               |
|   A change to the Idea's problem or solution changes the ancestor of every claim; by claim it still reaches        |               |
|   everything, which is the right answer by the right rule.                                                         |               |
|   Purple is removed the moment any leaf leaves done.                                                               |               |
|                                                                                                                    |               |
| Run drop-down immediately after the change, again in Look 2 before every outbound message, and again before Apply. |               |
| A completed leaf cannot remain done merely because it passed against a claim that has since moved.                 |               |
|                                                                                                                    |               |
| PROOF RECORD: exact claim + source/version + Plan refs + Spec refs + Design refs + Experience refs + Idea          |               |
| Problem/Solution refs + artifact refs + evidence (with executor) + pass/gap/conflict/waiver + earliest repair      |               |
| target + owner.                                                                                                    |               |
| Closure is structural, not a hidden score: every required claim passes or has an explicit, unexpired waiver, and   |               |
| no unresolved gap/conflict/stale dependency remains.                                                               |               |

| DONE - A STATE, NOT A NODE: THE IDEA'S SOLUTION, SATISFIED                                                         |               |
|-----------------------------------------------------------                                                         |               |
| Done is reached when the artifact on main satisfies the Idea's solution and the proof says so in both directions.  |               |
| There is no node named Done and no node named Final Product; the project turns purple.                             |               |
|                                                                                                                    |               |
| Required before purple:                                                                                            |               |
|   every required leaf done on main; a built and tested artifact with a resolvable primary URI and an integrity     |               |
